# 朗读内容不是正文修复方案

> 状态：代码修复与单元测试已完成，最终人工验收按第 5 节流程执行。
> 适用范围：微信读书网页版 + 本仓库 Tampermonkey 增强脚本。
> 测试方式：开发期完成真实抓包与单元测试，最终由用户在浏览器中按文末流程人工验证，不依赖自动浏览器 debug。
> 构建版本：必须安装 `dist/weread.user-1.24.0.js`，旧版 `1.23.0` 不含本次 `/web/book/chapter/e_*` 接口兜底。

## 1. 问题现象

点击控制面板中的“朗读”按钮后，语音虽然能开始播放，但朗读内容不是当前章节正文，常见表现：

- 朗读顶部栏、书名、章节名、上一章/下一章、目录、书架等 UI 文案；
- 朗读书评、推荐、简介、完本排行等页面文案；
- 朗读解密后的页面外壳或章节元数据；
- Canvas 阅读器下只能拿到当前视口或乱序单字；
- 页面阅读完成一章并自动跳转到下一章后，再点击“朗读”，朗读文本与当前页面正文不一致，仍读到上一章或错误章节的内容。

上一轮“未找到章节正文”修复后，提取器已经能拿到“看起来有文字”的候选；问题变成这些候选被弱判断放行，或者旧提取链路对 Canvas 阅读器根本不可达，最终把错误文本交给 `SpeechSynthesis`。

## 2. 功能调用链

```text
controlPanel 渲染 #ttsToggleBtn
  -> voiceRead.toggle()
  -> voiceRead.loadAndSpeak()
  -> voiceRead.extractReadableChapter()
  -> extractor.extractCurrentChapterText()
      -> collectEntries()                // 收集加密正文条目
      -> decryptEntry()                  // 解密渲染正文
      -> getRenderedHtml()               // 收集解密结果
      -> readPreRenderDom()              // 读取预渲染 DOM
      -> findCachedPlaintext()           // 读取 vm 缓存明文
      -> apiChapter.waitForChapter()     // 兜底：e_* 接口正文缓存
  -> 提取结果交给 chunker 分块
  -> speechEngine.speak(chunks)
```

每个候选源在进入朗读链路前都要经过 `isLikelyChapterText()` 判断；本次新增的接口兜底位于解密、预渲染 DOM、缓存全部失败之后。

## 3. 根因分析

### 3.1 文本合法性判断过宽

原 `chunker.isPlausibleText()` 只检查：

- 归一化后长度 ≥ 12；
- 包含 CJK 字符或连续 4 个英文字母。

顶部栏、书评区、推荐位、书籍简介等文本通常都满足这两个条件，因此会被当成正文。

### 3.2 缓存明文优先顺序固定，未比较正文度

`findCachedPlaintext()` 原先按字段优先级选择，`preRenderHtml` 优先级最高，只要文本通过弱判断就采用。当 `preRenderHtml` 里是书评、简介或渲染外壳，而 `tempContent` 才是正文时，脚本会优先朗读错误字段。

### 3.3 解密结果取“第一个可用”，未比较正文度

`getRenderedHtml()` 原先使用 `find()` 返回第一个通过弱判断的候选。如果解密函数先返回一段长 UI 文案，`tempContent` 随后才更新为正文，脚本会取到 UI 文案。

### 3.4 元数据字段可能被当成加密正文条目

`collectEntries()` 扫描 `Chapter` / `Section` 等名称时，可能把 `currentSection`、`chapterInfo`、`nextChapter` 等元数据对象当成加密正文条目，随后触发无意义的解密并污染结果。

### 3.5 Canvas 阅读器主提取链路不可达，文本层字符 DOM 顺序乱序

目标书籍页面使用微信读书的 Canvas 阅读器，浏览器回测得到两个关键事实：

- 站点的模块加载入口被包装成混淆引导函数，脚本通过 `unsafeWindow.Function` 注入 Webpack require 无法命中模块，旧链路只能拿到 `uid=''` 和空正文；
- `#renderTargetContent .passage-content` 内的 `[data-wr-role="text"]` 字符 span 虽然是绝对定位的，但字符在 DOM 中的顺序与视觉阅读顺序不一致，直接按 DOM 顺序拼接会得到乱序文字；
- 每个字符 span 的 `getBoundingClientRect()` 携带真实行/列坐标，按 y 分行、行内按 x 排序即可完整还原正文。

文本层兜底依赖当前视口内可测量的字符 span；章节自动跳转后，旧视口、旧预渲染 DOM 和旧缓存都可能残留，导致“朗读文本和正文不一样”。

### 3.6 Canvas 阅读器正文由 `/web/book/chapter/e_*` 接口下发，旧链路不覆盖

真实抓包确认，同一章节会并发请求多个资源：

- `https://weread.qq.com/web/book/chapter/e_0`：封面 XHTML；
- `https://weread.qq.com/web/book/chapter/e_1`：正文 XHTML；
- `https://weread.qq.com/web/book/chapter/e_2`：CSS；
- `https://weread.qq.com/web/book/chapter/e_3`：正文 XHTML。

响应体不是标准 DES 密文，而是“约 32 字节随机前缀 + base64 明文”。解码时必须逐偏移扫描，因为随机前缀会让 base64 从多个偏移解出“二进制噪音 + HTML 片段”。

### 3.7 错误偏移候选的评分会反超完整候选

回归测试复现了一个更隐蔽的问题：部分错误偏移能解出从 `class="content">正文...` 开始的残段。它没有合法 HTML 起始标签，但：

- 正则内容标记能命中 `class="content"`；
- 文本头部多出一段英文属性残片，`scoreChapterText()` 反而比干净正文多 1 分；
- 原实现没有“解码结果必须从合法 HTML 起点开始”的校验，也没有同分时对完整文档结构的偏好。

因此接口兜底自身也可能选中残段，把 `class="content">...` 读进语音。

## 4. 修复内容

### 4.1 增加正文度评分

文件：`src/modules/reading/voiceRead/chunker.js`

- 新增 `UI_NOISE_RE`，覆盖 `上一章`、`下一章`、`目录`、`书架`、`书评`、`推荐`、`简介`、`加入书架`、`朗读`、`语速`、`作者有话说`、`本章导读` 等 UI/导航短语；
- 新增 `scoreChapterText()`：文本长度、CJK 占比、句末标点、逗号密度给正分；UI 短语数量与密度、过多空格、无标点且含多个 UI 词给负分；
- 新增 `isLikelyChapterText()`：`isPlausibleText(text) && scoreChapterText(text) > 0`。

### 4.2 所有提取路径统一使用正文度判断

文件：`src/modules/reading/voiceRead/extractor.js`

- `findCachedPlaintext()` 不再固定让 `preRenderHtml` 优先，改为在通过正文度判断的候选中选择分数最高者；
- `getRenderedHtml()` 遍历所有解密结果与渲染字段，选择正文度最高候选；
- `capturePreRenderDom()` 在预渲染节点中选正文度最高的节点；
- `getLegacyDomText()` 的章节选择器和普通容器扫描都改为按正文度选最优；
- 新增 `METADATA_KEY_RE` 和 `isLikelyEncryptedEntry()`，避免元数据字段冒充加密正文条目。

### 4.3 Canvas 文本层按视觉坐标重排乱序字符

文件：`src/modules/reading/voiceRead/extractor.js`

- 新增 `reconstructTextLayerPageText()`：按 `getBoundingClientRect()` 的 y 坐标分行、行内按 x 坐标排序，再拼接可读正文；
- 新增 `getTextLayerLineThreshold()`：根据字符行高动态计算行簇阈值；
- 新增 `isTextLayerPageVisible()`：只取当前视口或视口前方 600px 内的分页，避免把已翻过的旧页文字混进当前朗读；
- 预渲染 DOM 兜底继续用克隆清理逻辑，移除 `style/script` 后若没有正文则返回空串。

### 4.4 新增 e_* 接口正文缓存模块

文件：`src/modules/reading/voiceRead/apiChapter.js`（本次新增）

- 在主世界 hook `fetch` 和 `XMLHttpRequest`，只截获 `/web/book/chapter/e_[^/]*` 请求；
- 从 POST body 的 `c` 字段取 chapterUid、`b` 字段取 bookId；
- 对每个响应扫描偏移 0 到 160，逐个 base64 解码，用 `chunker` 评分筛选正文候选；
- 排除封面（`<?xml`、`<head>`）和 CSS；
- 新增“必须从合法 HTML 起点开始”校验，拒绝 `class="content">...`、`>...`、`/>...` 等标签残段；
- 同分时优先结构更完整的候选：`<!DOCTYPE` > `<html` > `<head/body` > `<p`；
- 缓存按 chapterUid + bookId 隔离，最多保留 40 个章节，避免翻章后无限增长；
- 只有至少包装一个传输层后才标记 `__wrApiHooked`，避免页面 `fetch` 尚未赋值时丢失 hook。

### 4.5 提取器接入接口兜底

文件：`src/modules/reading/voiceRead/extractor.js`

- 在解密、预渲染 DOM、缓存全部失败后，追加接口兜底：

```js
const apiResult = uid
  ? await apiChapter.waitForChapter(uid, { bookId, timeout: 3000, interval: 80 })
  : apiChapter.getChapterText('', { bookId });
```

- 返回值必须满足 `chapterUid` 与当前章节一致，才允许进入朗读链路；
- `extractor.clearCache()` 同步清空 `apiChapter` 缓存，避免脚本重载后残留旧章节正文。

### 4.6 初始化时尽早安装网络 hook

文件：`src/modules/reading/voiceRead/index.js`

- `voiceRead.init()` 在启动预渲染观察器之前调用 `apiChapter.ensureHooked()`；
- `apiChapter.js` 模块顶层也会调用一次 `ensureHooked()`，保证模块加载即开始捕获。

## 5. 分步骤测试流程

> 本流程由用户人工执行，不包含自动浏览器 debug 环节。
> 目标页面：
> <https://weread.qq.com/web/reader/49432980720c671f4941767k9a132c802349a1158154a83>

### 前置条件

1. 已登录微信读书，能正常打开目标书籍正文页。
2. 确认 Tampermonkey 中安装的是最新构建：

```bash
npm run build
```

安装 `dist/weread.user-1.24.0.js`，旧版 `1.23.0` 没有接口兜底，不能用于本轮验收。
3. 浏览器建议优先 Chrome，失败时换 Edge 再测一次。
4. 目标页面应保持正文完整渲染，不要开启翻译类插件。

### 测试步骤

1. 打开目标正文页，等待章节正文完整渲染。
2. 打开脚本控制面板，确认当前阅读模式为“语音阅读”。
3. 目视确认当前视口正文首句。
4. 点击“朗读”按钮。
5. 立刻听语音前 3 至 5 句，并与当前视口正文首段对照：
   - 成功预期：语音从正文首句开始，不包含“上一章/下一章/目录/书架/书评/推荐/加入书架”等 UI 文案，不以 `class="content">`、`>正文` 等 HTML 残段开头；
   - 失败现象：语音朗读书名、章节名、导航按钮、书评、推荐、简介、乱序单字，或带 HTML 残段。
6. 观察页面提示：
   - 成功预期：`已提取正文 N 字`，N > 0；
   - 若失败：记录提示内容与控制台 `[WereadTTS]` 诊断。
7. 在当前章节内翻页，再次点击“朗读”：
   - 验证语音仍从当前章节正文开始，不串到已翻过的旧页文字。
8. 复现“阅读完成一章后自动跳转到下一章”：
   - 手动进入下一章，或让自动翻章流程完成跳转；
   - 等待 2 至 3 秒，让页面发出新的 `e_*` 接口请求；
   - 点击“朗读”，验证语音从新章节正文开始；
   - 重点确认没有读到上一章结尾、上一章标题或旧视口文字。
9. 刷新页面，等待 3 秒以上，重复步骤 2 至 8，排除缓存和时序影响。
10. 在 Chrome 和 Edge 各执行一次完整流程，记录结果。

> 若步骤 8 仍异常，打开浏览器开发者工具 Console，筛选 `WereadTTS`，记录 `source`、`uid`、`entryCount`、`domHits`；本轮修复后 `source` 可能是 `API:chapter`，`uid` 应与当前章节一致。

### 验收标准

| 项目 | 通过标准 |
| --- | --- |
| 正文首句 | 语音从当前章节正文首句开始，不朗读导航/UI 文案 |
| 朗读内容 | 无书名、章节名、上一章/下一章、目录、书架、书评、推荐、简介，无逐字空格、乱序单字或 HTML 残段 |
| 提示 | 显示“已提取正文 N 字”，N > 0 |
| 翻章 | 自动跳转下一章后再次朗读，内容为新章节正文，不串章 |
| 控制台 | 无新的“朗读内容错误”相关警告 |
| 浏览器兼容 | Chrome、Edge 至少一个稳定通过 |
