# 朗读无法获取章节正文修复方案

> 状态：已按方案完成代码修复与单元测试，浏览器人工回测按第 5 节执行。
> 适用范围：微信读书网页版 + 本仓库 Tampermonkey 增强脚本。
> 测试方式：由用户按文末“分步骤测试流程”人工验证，本方案不包含自动浏览器 debug 环节。

## 1. 问题现象与提示来源

点击控制面板中的“朗读”按钮后，页面出现提示：

```text
未找到章节正文，请打开书籍正文页后重试
```

该提示来自 [src/modules/reading/voiceRead/index.js](src/modules/reading/voiceRead/index.js) 的 `loadAndSpeak`：

```js
if (!result) {
  const message = options.continuation
    ? '下一章正文加载失败，连续朗读已停止，请重试'
    : '未找到章节正文，请打开书籍正文页后重试';
  utils.notificationManager.show(message);
  this.stop({ silent: true, hideBar: false });
  return;
}
```

同时浏览器控制台通常会出现：

```text
[WereadTTS] 未找到章节正文 { uid, expectedChapterUid, source, vueInstanceCount, entryCount, preferredEntryCount, ... }
```

该警告来自 [src/modules/reading/voiceRead/extractor.js](src/modules/reading/voiceRead/extractor.js) 的 `warnExtractionFailure`。

## 2. 功能调用链

“朗读”按钮到“未找到章节正文”的完整链路如下：

## 3. 静态代码根因分析

### 3.1 阅读器上下文识别依赖微信读书旧版字段

`refreshReaderContext` 通过以下方式识别阅读器状态：

- `getStore` 只认 `vm.$store` 和 `store.state`；
- `getReaderState` 只认 `store.state.reader`；
- `findReaderVms` 识别新渲染器的条件固定为：
  - `'tempContent' in vm`
  - `'isShowPreRender' in vm`
  - `vm.getCurrentSection != null`
  - `vm.currentChapter && vm.currentChapter.chapterUid`
- `getCurrentChapterUid` 只认：
  - `readerState.currentChapter.chapterUid`
  - `readerState.currentSection.chapterUid`
  - `vm.currentChapterUid`
  - `vm.currentChapter.chapterUid`

如果微信读书升级后调整了状态树、组件字段名或章节字段结构（例如 `currentChapter` 改成 `currentBookSection`、`chapterUid` 改成 `chapterId`、`reader` 改成 `readerState` 等），上述识别会全部落空：

- `store` / `readerState` 为 `null`；
- `readerVms` 为空或只找到没有解密能力的组件；
- `uid` 为空；
- `collectEntries` 拿不到条目；
- 即使 DOM 中存在正文，兜底逻辑也会因条件过严而失败。

### 3.2 加密正文条目形状被硬编码

`normalizeEntries` 对每个条目有两条硬性要求：

```js
if (!entry || typeof entry.value !== 'string' || typeof entry.valueHasStr !== 'function') return;
```

也就是说：

- `entry.value` 必须是 `string`；
- `entry.valueHasStr` 必须是函数。

当前微信读书若把加密正文改成：

- `entry.value` 是对象（例如 `{ data, nonce }`）；
- `valueHasStr` 改名或改为非函数；
- 正文存在 `entry.content` / `entry.html` / `entry.raw`；
- 或者条目结构是数组而非对象；

那么所有条目都会被静默丢弃，`entryCount` 直接为 0，后续解密和渲染完全不会执行。

### 3.3 正文数据源枚举范围过窄

`collectEntries` 只扫描：

- `readerState.horizontalReaderChapterContentHtml`
- `readerState.chapterContentHtml`
- `readerState` 中名称匹配 `/(ContentHtml|ChapterContent|RenderContent)/i` 的字段
- `vm.horizontalReaderChapterContentHtml`
- `vm.chapterContentHtml`

如果新版数据改存到：

- `store.state.reader.renderData`
- `store.state.reader.chapterMap`
- `vm.renderChapters`
- `vm.chapterContent`
- 某个嵌套对象内部
- 其它组件实例上

那么即使页面已经加载完正文，脚本也收集不到任何条目。

### 3.4 解密执行对象集合受限，且只认固定方法签名

`extractCurrentChapterText` 调用：

```js
const { instances, readerVms, vm, readerState, uid, source } = refreshReaderContext();
const entries = collectEntries(readerState, vm, uid);
```

解密时传给 `decryptEntry` 的是 `readerVms`，不是全部 `instances`：

```js
const html = await decryptEntry(readerVms, item.entry, ...);
```

如果具备 `decryptRenderHtml` / `preRender` 能力的组件没有被 `findReaderVms` 识别，即使它存在于 `instances` 中也不会被尝试。

webpack 兜底桥接 `findWebpackReaderBridge` 也存在限制：

- 只在“没有 store”或“readerVms 中没有任何 `decryptRenderHtml`”时触发；
- 模块扫描深度只有 2；
- 只找 `value.decryption`，且按固定参数顺序调用：

```js
decryptRenderHtml(value, bookId, chapterUid, sectionIndex)
```

若新版模块把解密函数放到别的字段、改成新签名，或需要额外参数，该兜底也会失效。

`runRenderer` 只接受三种结果：

- 返回值是字符串；
- `vm.tempContent` 变化；
- `vm.preRenderHtml` 变化。

如果解密结果写入了新字段（例如 `vm.renderHtml`、`vm.currentSectionHtml`），即使解密成功也会被判定为空。

### 3.5 DOM 兜底条件过严

预渲染 DOM 读取 `readPreRenderDom`：

- 有 `uid` 时要求缓存章节 uid 与当前 uid 完全一致；
- 没有 `uid` 时要求缓存节点仍然 `isConnected`。

因此只要 uid 识别失败或缓存节点被移除，该兜底就会返回 `null`。

旧版 DOM 读取 `getLegacyDomText` 更严格：

```js
if (el.querySelector('canvas, button, input, textarea, select')) continue;
```

当前微信读书正文使用 canvas 渲染，正文容器内通常存在 canvas，因此第一个合法选择器就会被跳过，随后：

```js
if (document.querySelector('.wr_canvasContainer, .readerChapterContent canvas')) return null;
```

直接返回空。也就是说，新版 canvas 阅读器下旧 DOM 兜底基本不可用。

此外，`chunker.isPlausibleText` 要求归一化后长度不少于 12 且包含 CJK 或连续 4 个英文字母。短章节、只有少量文字的内容页仍可能被误判为“不可读”，但这不是本次主因。

### 3.6 时序与重试不足

`waitForPageTurn` 最长只等待 2.2 秒，`extractReadableChapter` 默认只重试 3 次，间隔为 `400 + attempt * 200` 毫秒。若点击“朗读”时章节内容仍在加载、预渲染尚未完成，第一次提取必然失败，剩余重试也未必能等到内容稳定。

### 3.7 失败诊断信息不足以定位

`warnExtractionFailure` 只输出：

- `uid`
- `expectedChapterUid`
- `source`
- `vueInstanceCount`
- `entryCount`
- `preferredEntryCount`
- canvas 是否存在
- 文本层节点数量
- webpack 诊断

缺少：

- 实际扫描到的 `readerState` 顶层 key；
- 每个候选条目 `entry.value` 的类型和可用字段；
- 所有具备 `decryptRenderHtml` / `preRender` 能力的组件数量；
- 尝试解密时每个组件的错误信息；
- DOM 兜底各选择器的命中情况。

这些信息对区分“状态字段变了”“条目结构变了”“解密失败”“DOM 兜底失败”非常关键。

## 4. 修复方案

以下为建议实施顺序，按优先级排列。实施后按第 5 节流程回测。

### P0-1 通用化阅读器上下文发现

修改 `refreshReaderContext`：

- 遍历全部 `instances`，不只找 `$store`，还查找：
  - `vm.$store`
  - `vm.proxy.$store`
  - 组件数据中的 `store` / `readerStore`
  - `store.state.reader`
  - `store.state.readerState`
  - `store.state.book.reader`
  - 组件上的 `readerState` / `readerData`
- 扩展 `findReaderVms` 识别条件，命中任意一项即视为候选：
  - `decryptRenderHtml`
  - `preRender`
  - `preRenderHtml`
  - `tempContent`
  - `isShowPreRender`
  - `chapterContentHtml`
  - `horizontalReaderChapterContentHtml`
  - `currentChapter`
  - `currentChapterUid`
  - `currentSection`
  - `getCurrentSection`
  - `getCurrentSectionIdx`
- 返回全部候选，不要只保留第一个；
- `getCurrentChapterUid` 增加候选字段：
  - `currentChapter.chapterUid`
  - `currentChapter.chapterId`
  - `currentSection.chapterUid`
  - `currentSection.chapterId`
  - `currentBookSection.chapterUid`
  - `vm.chapterUid`
  - `vm.bookSection.chapterUid`
  - 数值型字段统一转字符串后比较。

### P0-2 放宽加密条目归一化

修改 `normalizeEntries`：

- 允许 `entry.value` 为字符串；
- 允许 `entry.value` 为对象，并从对象中继续取：
  - `entry.value.value`
  - `entry.value.data`
  - `entry.value.html`
  - `entry.value.content`
  - `entry.value.raw`
- 不再强制要求 `typeof entry.valueHasStr === 'function'`，改为可选能力：
  - 有 `valueHasStr` 时用它判断是否包含正文；
  - 没有时用“字段是否为非空字符串或可解出字符串”判断；
- 章节 uid 从以下字段依次推导：
  - `entry.chapterUid`
  - `entry.chapterId`
  - `entry.uid`
  - `entry.chapter.chapterUid`
  - 容器 key（对象键）
  - 当前章节 fallback
- 为每个条目保留 `raw` 和 `valueType`，供诊断输出。

### P0-3 扩大正文数据源枚举

修改 `collectEntries`：

- 保留现有固定 key；
- 对 `readerState`、`vm`、`store.state` 做浅层到 2 层的递归扫描；
- 命中以下特征即纳入候选：
  - key 包含 `ContentHtml` / `ChapterContent` / `RenderContent` / `PreRender` / `Chapter` / `Section`
  - value 是数组或对象，且内部存在字符串字段
- 排除已知噪音：
  - `Target`
  - `Highlight`
  - `Selection`
  - UI 配置、设置对象
- 同时从全部 `instances` 上收集候选，而不是只看 `readerState` 和第一个 vm。

### P1-1 增强解密与渲染结果收集

修改 `decryptEntry` 和 `runRenderer`：

- 解密候选组件 = `readerVms` + 全部 `instances` + webpack 桥接 vm，去重；
- 对每个 `decryptRenderHtml`，依次尝试多种调用方式：
  1. `(value, bookId, uid, sectionIndex)`
  2. `(value, uid, sectionIndex)`
  3. `(value, uid)`
  4. `(value)`
- 记录每个组件和每种调用的错误，不要静默吞掉；
- `runRenderer` 的结果收集扩展为：
  - 返回值字符串
  - `vm.tempContent`
  - `vm.preRenderHtml`
  - `vm.renderHtml`
  - `vm.currentSectionHtml`
  - `vm.chapterContentHtml`
  - `vm.preRenderContent`
- 仅当所有正常路径失败时，才尝试 `isShowPreRender` 切换和 `preRender(uid)`，且必须在 finally 中恢复原状态。

### P1-2 放宽 DOM 兜底

修改 `readPreRenderDom` 和 `getLegacyDomText`：

- 预渲染 DOM 优先读取：
  - `#preRenderContent`
  - `#preRenderContents`
  - `.preRenderContent`
  - `.preRenderContainer`
  - `#renderTargetContent`
  - `[data-wr-role="text"]` 文本层
- 只有同时存在多个不同章节文本时才要求 uid 匹配；只有一个合理文本时直接采用；
- 缓存节点即使被移除，只要 html 缓存仍有文本且不是过期章节，也允许使用；
- 旧版 DOM 扫描不再因为容器内有 canvas 就跳过整个容器：
  - 先取 canvas 之外的文本节点；
  - 再取 `#renderTargetContent` 文本层；
  - 最后才扫描普通容器；
- `getLegacyDomText` 的“发现 canvas 立即返回 null”改为“先尝试所有文本来源，全部失败才返回 null”。

### P1-3 时序与重试

- `waitForPageTurn` 最长等待时间从 2.2 秒提高到 5 秒；
- `extractReadableChapter` 在正文仍未加载时增加重试次数，例如 5 次；
- 重试间隔从固定短间隔改为递增间隔；
- 在重试前检查“当前章节 uid 是否已经稳定且不等于空”，避免在页面切换瞬间反复提取旧章节。

### P2-1 失败诊断增强

扩展 `warnExtractionFailure` 输出：

- `readerState` 顶层 key 列表；
- 候选条目数量、`value` 类型分布、是否有 `valueHasStr`；
- 具备 `decryptRenderHtml` / `preRender` 能力的组件数量；
- 每个解密候选组件的调用错误摘要；
- DOM 各选择器命中数量；
- 建议采用 `console.group` 输出完整诊断，避免 JSON 过长被截断。

### P2-2 补充单元测试

在 `test/` 下增加：

- `normalizeEntries` 兼容“新版条目对象结构”的测试；
- `collectEntries` 兼容“新 key + 嵌套结构”的测试；
- `getCurrentChapterUid` 兼容 `chapterId` 的测试；
- `extractCurrentChapterText` 在“无 uid + 只有一个预渲染 DOM”时应成功降级的测试。

## 4.1 修复落地记录

已修改文件：

- `src/modules/reading/voiceRead/extractor.js`
- `src/modules/reading/voiceRead/index.js`
- `test/extractor.test.js`

主要落地内容：

- 阅读器上下文发现：兼容 `readerState` / `readerData` / `book.reader` / `bookId` 等字段，`getCurrentChapterUid` 兼容 `chapterId`。
- 条目归一化：允许字符串、数组、对象 map、`entry.value` 嵌套对象，以及 `data.ciphertext` 等多层加密字段。
- 数据源枚举：对 `readerState`、`vm` 和全部组件实例扫描 2 层 `ContentHtml` / `ChapterContent` / `RenderContent` / `PreRender` / `Chapter` / `Section` 字段，并排除 UI 噪音字段。
- 解密调用：按方法参数长度选择签名，优先 `(value, uid, sectionIndex)`，避免 4 参数签名误用当前页分段索引；webpack 桥接统一走 3 参数入口并固定标记。
- webpack 兜底：不再只在“没有 Vue 解密器”时启用，Vue 解密失败时也会把 webpack 桥接加入候选。
- 渲染结果收集：覆盖 `tempContent`、`preRenderHtml`、`renderHtml`、`currentSectionHtml`、`chapterContentHtml`、`preRenderContent`、`renderedHtml`、`horizontalReaderChapterContentHtml`。
- 缓存明文兜底：条目解密全部失败时，仍会尝试读取组件上已渲染的 `tempContent` / `preRenderHtml` 等字段。
- DOM 兜底：canvas 阅读器先读文本层和预渲染 DOM；无 uid 时允许使用单个预渲染 DOM；缓存节点被移除后仍可读取 html 缓存。
- 时序重试：翻页等待提高到 5 秒，非续读提取次数提高到 5 次，重试间隔递增。
- 失败诊断：新增 `readerStateKeys`、`entryValueTypes`、`readerVmCount`、`decryptorCount`、`decryptErrors`、`domHits` 等字段。

## 5. 分步骤测试流程

> 本流程由用户人工执行，不需要自动浏览器 debug。
> 目标页面：
> <https://weread.qq.com/web/reader/49432980720c671f4941767k9a132c802349a1158154a83>

### 前置条件

1. 已登录微信读书，能正常打开目标书籍正文页。
2. 本仓库已完成构建并安装到 Tampermonkey：

```bash
npm run build
```

3. 浏览器建议优先 Chrome，失败时换 Edge 再测一次。

### 测试步骤

1. 打开目标正文页，等待章节正文完整渲染。
2. 打开脚本控制面板，确认当前阅读模式为“语音阅读”。
3. 点击“朗读”按钮。
4. 观察页面右上角或控制面板提示：
   - 成功预期：`已提取正文 N 字`，其中 N 为实际正文字数；
   - 失败现象：`未找到章节正文，请打开书籍正文页后重试`。
5. 若成功，继续观察：
   - 语音是否开始播放；
   - 浮动快捷栏是否出现；
   - 页面滚动是否与朗读进度同步；
   - 暂停、继续、停止按钮是否正常。
6. 若失败，打开浏览器开发者工具 Console，筛选 `WereadTTS`：
   - 找到 `[WereadTTS] 未找到章节正文` 警告；
   - 展开并记录诊断对象；
   - 重点记录：`uid`、`source`、`vueInstanceCount`、`entryCount`、`preferredEntryCount`、`canvas`、`textLayerNodeCount`、`foundStore`、`foundDecryption`。
7. 刷新页面，等待 3 秒以上再执行步骤 2 到 4，排除缓存和时序影响。
8. 翻到下一章，再次点击“朗读”：
   - 验证单章朗读；
   - 验证章节切换后的连续朗读。
9. 在 Chrome 和 Edge 各执行一次完整流程，记录结果。
10. 若仍失败，把步骤 6 得到的完整诊断 JSON 连同浏览器版本、微信读书页面版本一起反馈。

### 验收标准

| 项目 | 通过标准 |
| --- | --- |
| 首次点击“朗读” | 显示“已提取正文 N 字”，N > 0 |
| 控制台 | 无 `[WereadTTS] 未找到章节正文` 警告 |
| 语音 | 正常播放，可暂停、继续、停止 |
