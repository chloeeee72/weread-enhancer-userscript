# TTS 语音与页面滚动精确同步方案

## 0. 实施状态（2026-08-14）

本仓库现有 Web Speech 能力已经完成阶段一和阶段二落地：

- chunk 使用整章绝对 UTF-16 偏移，不再依赖裁剪后字符串长度反推位置。
- `onboundary`、chunk 起止事件进入连续语音字符时钟，新观测不直接跳改当前位置。
- 移除块内 85%/90% 封顶和块结束百分比补跳。
- 播放前建立预渲染 DOM 行级 y 表，并完成首字平滑定位后才发声。
- 语音模式改用 `requestAnimationFrame` 前馈 + 闭环滚动控制。
- y 校正统一减去视口阅读焦点；大误差先暂停语音，滚动对齐后恢复。
- 范围绝对偏移、暂停耗时、语速/音色切换、翻章、后台、手动滚动和页面重排边界已经接入。
- 无 `boundary` 音色使用按音色、语速和浏览器保存的历史 CPS 模型降级。
- 已增加纯模型自动测试，覆盖文本偏移、语音时钟连续性和滚动控制器收敛。

阶段三仍需要外部条件：接入能够返回音频和字/词时间戳的 TTS 实现及其鉴权/部署配置。仓库当前没有该服务，因此现有默认模式仍是 Web Speech 高精度兼容模式，不能把缺少 `boundary` 的首次新音色标记为严格同步。

## 1. 结论

当前实现无法通过继续调整一个固定字速或增加 y 校正频率达到严格同步。问题本质是三套坐标没有共享同一条时间线：

1. 语音位置：浏览器当前读到哪个字符。
2. 文本位置：该字符在整章规范化文本中的绝对偏移。
3. 页面位置：该字符排版后所在行对应的实际文档 y。

目标方案必须改成“语音时钟驱动的闭环跟随”：

- 播放前建立稳定的“时间 -> 字符 -> 页面 y”映射。
- 播放中以真实音频时间或 `boundary` 事件为观测，不再以固定字/秒作为主时钟。
- 每帧计算目标 y，同时用前馈速度跟随语音，用闭环误差平滑消除小偏差。
- 任何新校准值都通过连续过渡进入控制器，禁止直接改 `scrollTop`。
- 出现大幅重排、失去时间基准或目标跳变时，暂停语音，平滑重新定位，稳定后继续。不能让语音继续播放而页面在后面追赶。

严格意义的“完美同步”需要 TTS 引擎提供音频及字/词时间戳。现有 `window.speechSynthesis` 不提供可读取的音频播放时钟，`boundary` 也不是所有浏览器和音色都支持，因此只能做到高精度兼容模式，不能对所有环境承诺严格同步。

最终建议保留两档能力：

| 模式 | 时间基准 | 可承诺结果 |
| --- | --- | --- |
| 严格同步模式 | 可读取 `currentTime` 的音频 + 字/词时间戳 | 从首字开始稳定同步；可量化验收 |
| Web Speech 兼容模式 | `onboundary` + 自适应预测 + `onend` | 支持边界事件时接近严格同步；不支持时只能平滑估算 |

若产品要求在所有支持环境中都“完美”，严格同步模式应是默认模式；Web Speech 只能作为降级方案。

## 2. 落地前实现为何先慢后追、仍需反复校正

### 2.1 播放早于初始定位

`voiceRead.loadAndSpeak()` 当前先启动自动滚动和语音，再异步测量范围位置：

1. `autoRead.start()` 启动 20ms 定时器。
2. `speechEngine.speak()` 在 120ms 后开始发声。
3. `locateRangeBounds()` 异步测量，最长等待 600ms。
4. 测量结束后 `scrollToRangeStart()` 直接调用 `window.scrollTo()`。

结果是语音已经开始，页面却暂时保持原位；定位完成后页面瞬移。该启动顺序与“从第一声开始同步”直接冲突。

### 2.2 初始字速只是估值，且代码故意让页面更慢

没有 `boundary` 时，首块使用固定 `4.5 字/秒`。真实速度取决于音色、浏览器、语速档位、标点和文本语言，通常不会恰好等于该值。

完成一个 chunk 后才有第一个真实耗时样本。原实现又把样本均值乘以 `0.95`，明确采用“宁慢勿快”策略。因此页面天然落后，之后只能靠块边界补齐。

### 2.3 块内封顶造成“停住，然后补跳”

原进度逻辑：

- 有 `boundary` 时，当前块最多推进到 90%。
- 无 `boundary` 时，当前块最多推进到 85%。
- `onend` 后把整个块一次性记为完成。

因此每块末尾必然出现 10% 或 15% 的进度阶跃。自动滚动随后追赶新目标，这正是周期性停顿和跳动的主要来源之一。

### 2.4 `boundaryCharIndex` 是阶梯信号

当前只保存最近一次 `boundary` 的字符下标。两个事件之间字符位置不变化，页面停止；新事件到达时字符位置突然前移，页面追赶。

正确做法不是直接使用最近下标，而是保存带单调时钟的边界观测点，在两个观测点之间持续预测；新观测到来后平滑修正预测速度和相位。

### 2.5 线性字符比例不等于页面 y

当前基线是：

```text
已读字符占比 * 页面可滚动距离
```

真实排版包含标题、空行、图片、引用、段间距、不同字号和不同高度的行。相同字符数对应的像素高度不固定，因此线性映射必然持续漂移。

### 2.6 新锚点会改写当前目标

每个 chunk 开始时异步测量一个锚点。新锚点插入后，`interpolateAnchorErr()` 的结果可能立即变化，当前目标 y 随之阶跃。虽然自动滚动限制了单 tick 位移，但它仍表现为先落后、再快速追赶。

### 2.7 y 的语义不一致

`extractor.locateTextOffset()` 返回文字在文档流中的绝对 y；自动滚动需要的是 `scrollTop`。两者之间还应减去文字在视口内的阅读焦点位置：

```text
targetScrollTop = textDocumentY - viewportFocusY
```

当前锚点直接把 `textDocumentY` 当作 `scrollTop`。范围首次定位时另行减去 80px，但后续进度映射没有减，造成至少 80px 的系统性回拉。

### 2.8 范围偏移存在相对值和绝对值混用

以下值没有统一坐标系：

- chunk 累计字符数是所选范围内的相对偏移。
- `locateTextOffset()` 需要整章绝对偏移。
- `rangeStartIndex` 是整章绝对偏移。
- 未指定结束文字时，部分逻辑把 `textLength` 当作整章绝对结束偏移。

从章节中段开始朗读时，这会让锚点测量和目标字符位置产生确定性错误。

### 2.9 文本规范化会继续积累偏移误差

`chunkText()` 会 `trim()` 分句和片段，chunk 长度之和不保证等于范围文本长度。DOM 定位又逐个文本节点单独规范化并拼接，会丢失文本节点之间的空格。中文正文影响较小，英文、混排、强调标签和跨节点短语会持续漂移。

### 2.10 页面到底不应决定语音模式翻章

语音模式当前仍会因视口到达页底而进入翻页计时。严格同步下，翻章必须由“最后一个音频时间戳已播放完成”驱动。页面 y 只负责展示，不能成为播放状态的主时钟。

## 3. 可验收目标

“完美”需要先转成可测指标。建议严格同步模式使用以下标准：

1. 首次可听发声前，文本映射已建立，首字所在行已平滑移动到阅读焦点。
2. 播放期间，以音频时间戳对应文字行为基准，目标与实际 `scrollTop` 误差：正常状态 P95 不超过 3px，最大不超过 8px。
3. 画面不得出现单帧瞬移。正常状态单帧位移不超过 6px；快速追赶仍需满足加速度限制。
4. 新边界、新锚点、chunk 切换均不得造成目标 y 不连续。
5. 暂停期间滚动完全冻结；恢复后不回退、不补跳。
6. 语速变化、音色变化、窗口缩放、字体加载和图片加载后，重新同步过程中不允许语音与页面各自继续运行。
7. 章节首尾、页面不足一屏、指定范围、后台标签页、用户手动滚动等边界场景有确定行为。

Web Speech 兼容模式单独标注能力，不套用严格同步承诺。建议验收为：支持 `boundary` 的音色下，当前朗读行始终位于焦点带内，且无可见跳变；不支持时只要求平滑、误差不累积超过一个 chunk。

## 4. 统一数据模型

### 4.1 唯一文本坐标

提取正文后生成一次规范化文本，同时生成从规范化 UTF-16 偏移到 DOM 文本节点原始偏移的映射。后续所有模块只使用该坐标：

```js
{
  chapterText,
  rangeStartOffset,
  rangeEndOffset,
  chunks: [
    {
      text,
      startOffset, // 整章绝对 UTF-16 偏移
      endOffset
    }
  ],
  domOffsetMap
}
```

关键规则：

- `SpeechSynthesisEvent.charIndex`、JavaScript 字符串下标和 DOM Range 全部统一为 UTF-16 code unit。
- chunk 不再靠重新累加 `chunk.length` 推导全局偏移。
- 分句时保留原文本区间，不通过 `trim()` 后的长度反推位置。
- 规范化必须跨 DOM 文本节点运行，不能逐节点 `trim()` 后拼接。
- 所选范围只改变播放起止，不创建第二套相对坐标。

### 4.2 排版几何表

播放前一次性建立当前范围的行级几何表：

```js
{
  layoutVersion,
  viewportHeight,
  maxScrollTop,
  lines: [
    {
      startOffset,
      endOffset,
      top,
      bottom,
      centerY
    }
  ]
}
```

实现方式：

1. 从预渲染 DOM 的文本节点建立规范化偏移映射。
2. 使用 `Range.getClientRects()` 获取文本行矩形。
3. 将同一视觉行上的连续字符合并，保存行起止偏移和文档 y。
4. 标题、空段、图片和块间距自然体现在相邻行的 y 差中。
5. 只测量行边界，不逐字符永久保存矩形，控制内存和重排成本。

目标位置不再由整章字符比例计算，而由当前字符所在行直接得到：

```text
textY = interpolateLineY(spokenOffset)
desiredTop = clamp(textY - focusY, 0, maxScrollTop)
```

`focusY` 建议为视口高度的 38%，并加上实际固定顶栏高度。章节开头和末尾受滚动边界限制时，允许文字离开固定焦点，但字符与页面坐标仍保持正确。

### 4.3 语音时间线

严格同步引擎在真正播放前返回：

```js
{
  audio,
  marks: [
    {
      timeMs,
      startOffset,
      endOffset
    }
  ]
}
```

播放中用音频 `currentTime` 作为唯一主时钟，在相邻 mark 之间插值得到当前字符偏移。若底层支持更精确的输出时钟，应优先使用输出时间戳，避免仅依赖事件回调到达时间。

Web Speech 适配器输出同样的观测格式：

```js
{
  observedAt,
  startOffset,
  source: 'boundary' | 'chunk-end'
}
```

兼容模式使用最近若干观测点估算短期速度。模型必须同时估计：

- 相位：当前字符偏移。
- 速度：当前字符/秒。
- 置信度：边界事件的新鲜度和稳定性。

标点停顿不能被长期平均字速抹平。最近边界长时间不更新时，预测应逐步减速并停在下一个标点或当前 chunk 末端，而不是继续匀速穿过停顿。

## 5. 启动流程

点击“朗读”后必须按以下顺序执行：

```text
PREPARING_TEXT
  提取正文，生成带绝对偏移的 chunks

PREPARING_LAYOUT
  等待字体稳定，建立范围行级几何表

PREPARING_AUDIO
  严格模式生成音频与时间戳
  兼容模式检查 boundary 能力及历史音色模型

ALIGNING_START
  平滑滚动到首字目标位置
  连续 2 帧误差小于 2px 才算稳定

PLAYING
  启动音频和 requestAnimationFrame 同步控制器
```

核心约束：

- `PLAYING` 前不得发声。
- 初始定位不得调用瞬移式 `scrollTo()`。
- 准备失败时，不启动“假同步”滚动。应明确降级为仅朗读或兼容模式。
- 用户在准备期间再次点击停止、切换章节或修改范围时，通过 `sessionId`/`AbortController` 取消整条旧任务。

这会增加一次启动准备时间，但它是“从第一声开始同步”的必要成本。不能同时要求零准备时间、新音色首次使用、无时间戳，又要求首字严格同步。

## 6. 每帧滚动控制器

固定 20ms `setInterval` 改为 `requestAnimationFrame`。控制器每帧执行：

1. 读取真实音频时间或 Web Speech 预测字符位置。
2. 从几何表得到当前字符的 `desiredTop`。
3. 计算目标自身速度 `targetVelocity`，作为前馈项。
4. 计算实际位置误差 `error = desiredTop - actualTop`。
5. 用临界阻尼闭环生成修正速度。
6. 应用速度、加速度和滚动边界限制。

建议控制形式：

```text
commandVelocity = targetVelocity + Kp * error - Kd * actualVelocity
```

它与当前“目标差多少就追多少”不同：

- `targetVelocity` 负责与语音正常速度一致，不等误差出现才追。
- 比例项只消除小误差。
- 阻尼项抑制过冲和来回抖动。
- 加速度限制保证新观测或新锚点不会造成视觉跳变。

参数不应写成固定“每 20ms 最多 30px”。应按真实帧间隔 `dt` 计算，确保 60Hz、120Hz、掉帧和后台恢复时行为一致。

### 6.1 行间移动

同一行内字符 y 基本不变，因此页面不需要匀速移动。跨行时，把上一行 y 到下一行 y 的变化分配到一个短连续窗口内，建议 120-220ms，并以真实时间戳为中心。效果是：

- 读同一行时页面稳定。
- 读到下一行时页面平滑下移。
- 标点停顿时页面也停。
- 标题、图片和大段间距处按真实排版距离移动，而不是按字符数匀速穿过。

这比“整章始终缓慢滚动”更符合阅读视线，也更接近真正的语音位置。

### 6.2 小误差和大误差采用不同策略

建议分级：

| 误差 | 策略 |
| --- | --- |
| `<= 8px` | 正常闭环吸收，语音继续 |
| `8px ~ 0.2 viewport` | 提高修正增益，但仍受速度和加速度限制 |
| `> 0.2 viewport` 或布局版本变化 | 暂停语音，平滑滚到新目标，稳定后继续 |

大误差时暂停语音不是退让，而是严格同步的必要行为。让语音继续、页面快速追赶，本身就意味着一段时间内不同步。

## 7. 校准策略

### 7.1 禁止运行中直接修改坐标函数

新测量结果不能立刻替换旧几何值。应创建新 `layoutVersion`，并按以下方式提交：

1. 计算旧模型与新模型在当前字符位置的 y 差。
2. 差值小于阈值时，在 300-600ms 内对模型做连续混合。
3. 差值过大时进入 `REALIGNING`，暂停语音后完成滚动。
4. 混合结束后再丢弃旧模型。

这样任何 y 校正都是“滚动过去”，不会跳过去。

### 7.2 Web Speech 速度模型

不支持严格时间戳时，兼容模式使用：

- 每个 `boundary` 的全局字符偏移和 `performance.now()`。
- 最近窗口的稳健速度估计，过滤重复、倒退和离群事件。
- 相位锁定式修正：边界到达后在一个短时间窗内消化预测偏差，不瞬间改字符位置。
- 按 `voiceURI + lang + rate + browser` 保存历史模型，下一次点击即可从已有校准值启动。
- 不再乘 `0.95` 人为减速。
- 不再使用 85%/90% 块内封顶。

若首个音色无历史模型且不产生 `boundary`，首块严格同步在信息上不可实现。此时只能明确降级，不能用“后续自动校正”包装成完美同步。

### 7.3 chunk 结束

chunk 结束只用于确认边界，不应补跳剩余百分比：

- 严格模式的末端由最后一个时间戳确定。
- Web Speech 模式在接近 chunk 末端时让预测速度平滑收敛。
- `onend` 若仍有小偏差，通过相位修正窗消化。
- 偏差超过阈值则暂停下一块，先平滑对齐再开始下一块。

## 8. 边界问题

### 8.1 暂停与继续

- 暂停时冻结音频时钟采样、字符预测和滚动控制器。
- 恢复时先读取当前音频时间，重算目标；小误差平滑吸收，大误差先对齐再恢复。
- 当前暂停耗时计算存在重复扣除风险：既移动 `chunkStartTime` 又累计 `pausedTotalMs`。新模型只维护一个单调播放时钟，避免双重扣减。

### 8.2 实时修改语速

现有 Web Speech 会取消并重读整个当前 chunk，页面却仍以旧 chunk 位置为基础，容易重复和回退。

新方案：

- 严格模式从当前时间戳对应的词边界切分剩余文本，重新生成剩余音频和时间戳；全局字符偏移不归零。
- Web Speech 模式从最近确认的安全词边界重启，只允许有限回读，并同步回到该绝对偏移。
- 新旧时间线切换前进入短暂 `REALIGNING`，不能两边独立切换。

### 8.3 修改音色

按“新引擎会话”处理：取消旧事件，保留全局阅读偏移，从安全边界重新准备时间线。旧音色速度模型不得复用。

### 8.4 用户手动滚动

程序滚动与用户输入必须区分。检测 `wheel`、触摸、滚动键和滚动条拖动：

- 严格同步默认立即暂停语音和跟随。
- 用户停止操作后，以当前语音字符的目标 y 平滑重新对齐。
- 对齐稳定后才继续播放。

若选择“手动查看时语音继续”，就必须接受暂时不同步，不能同时满足严格目标。

### 8.5 页面重排

以下事件使几何表失效：

- 窗口大小、阅读宽度、字号或缩放变化。
- `document.fonts` 完成加载。
- 图片加载后高度变化。
- 正文 DOM、canvas 尺寸或章节内容变化。

通过 `ResizeObserver`、`MutationObserver`、字体事件和现有设置事件统一增加 `layoutVersion`。若变化影响当前或后续行，暂停语音、重建局部几何表、平滑对齐、继续播放。

### 8.6 标签页进入后台

后台标签页会暂停 `requestAnimationFrame`，而系统语音可能继续。严格模式在 `visibilitychange` 变为隐藏时暂停音频；回到前台后重新对齐再继续。不能依赖恢复时一次大滚动追上。

### 8.7 页面顶部和底部

使用：

```text
clamp(textY - focusY, 0, maxScrollTop)
```

顶部和底部无法把文字固定在 38% 视口处，这是物理边界，不是同步误差。首字和末字仍应对应正确页面位置。

页面不足一屏时 `maxScrollTop = 0`，禁用滚动控制，只保留语音时间线。

### 8.8 章节切换

- 翻章由语音播放完成事件触发，不由滚动到底触发。
- 旧章节的音频事件、异步定位和几何测量全部带 `sessionId`，切章后丢弃。
- 新章节重复完整准备流程，首字定位稳定后再发声。
- 未开启章节续读时，最后一个时间戳完成即停止，不额外滚动到底。

### 8.9 范围朗读

- `rangeStartOffset` 和 `rangeEndOffset` 始终是整章绝对偏移。
- 未指定结束文字时，结束值应为 `rangeStartOffset + rangeText.length`，不是单独的 `textLength`。
- 起点和终点都从统一 DOM 偏移表取 y。
- 首次定位与播放中映射使用同一个 `focusY`，不再一处减 80px、另一处不减。

### 8.10 DOM 不可测或 canvas 排版不一致

严格模式需要验证预渲染 DOM 与可见 canvas：

- 规范化文本长度和采样短语一致。
- 首、中、尾至少三个采样点的 y 单调且位于有效文档范围。
- 页面滚动后采样坐标保持稳定。

验证失败时，严格滚动不能启动。可提供“仅朗读”或“比例估算兼容模式”，但必须标明已降级。

### 8.11 标点、英文、数字、emoji 和不可读字符

- 时间戳必须绑定引擎实际使用的 utterance 文本，而不是原正文长度估值。
- 标点可有时间但没有独立发音，使用前后 mark 表达停顿。
- UTF-16 下代理对占两个 code unit，所有映射必须保持相同口径。
- 被 TTS 跳过的符号和空白映射到相邻可读 token，避免字符游标停在不可定位位置。

### 8.12 滚动受阻与浏览器原生平滑滚动

- 控制器启动时避免 `scroll-behavior: smooth` 与逐帧控制叠加；两套动画会互相追赶。
- 每帧读取实际 `scrollTop`，不能假设写入值已生效。
- 连续多帧写入后位置不变，判断为滚动容器错误、页面锁定或已到边界，不通过放大步长暴力突破。

## 9. 模块调整建议

建议将同步职责从 `autoRead` 和 `voiceRead` 中拆开，避免继续叠加条件分支：

```text
src/modules/reading/voiceRead/
  textTimeline.js       规范化文本、chunk 绝对偏移
  layoutMap.js          字符偏移到真实页面 y
  audioClock.js         严格音频时钟适配
  webSpeechClock.js     boundary 兼容适配
  scrollFollower.js     requestAnimationFrame 闭环控制
  syncSession.js        状态机、取消、重排和恢复
```

现有模块职责调整：

- `speechEngine.js`：只负责播放和发出结构化时间观测，不再保存供外部轮询的单个 `boundaryCharIndex`。
- `extractor.js`：返回规范化文本及 DOM offset map；提供批量行几何测量。
- `chunker.js`：返回 `{ text, startOffset, endOffset }`，不丢失源偏移。
- `voiceRead/index.js`：编排会话和 UI，不再计算滚动比例。
- `autoRead/index.js`：语音模式交给 `scrollFollower`；保留原自动阅读模式。
- `pace/index.js`：只管理用户语速设置和非语音自动阅读速度，不再作为语音当前位置主时钟。

## 10. 状态机

建议使用显式状态，避免多个布尔值组合出非法状态：

```text
IDLE
PREPARING_TEXT
PREPARING_LAYOUT
PREPARING_AUDIO
ALIGNING_START
PLAYING
PAUSED
REALIGNING
WAITING_NEXT_CHAPTER
STOPPED
ERROR
```

重要转换：

- `ALIGNING_START -> PLAYING`：位置稳定后才允许。
- `PLAYING -> REALIGNING`：大坐标误差、重排、语速/音色改变。
- `REALIGNING -> PLAYING`：页面稳定且时间线已重新锚定。
- 任意准备状态收到停止：取消所有异步工作并进入 `STOPPED`。
- 所有异步回调校验会话 token 和布局版本。

## 11. 实施顺序

### 阶段一：消除确定性跳动

1. 调整启动顺序：完成首字定位后再播放。
2. 初始定位和后续校正统一走滚动控制器。
3. 移除 85%/90% 封顶及块末一次性补齐。
4. 修复范围绝对偏移、`focusY`、暂停耗时和文本规范化坐标。
5. 语音模式翻章改由播放完成驱动。

该阶段能明显消除“停顿后跳跃”，但仍未满足新音色首次使用的严格同步。

### 阶段二：真实排版跟随

1. 建立统一 DOM offset map。
2. 播放前生成行级几何表。
3. 用 `字符偏移 -> 行 y -> targetScrollTop` 取代整章比例。
4. 引入 `requestAnimationFrame` 前馈 + 闭环控制器。
5. 完成重排、手动滚动、后台标签页和边界状态处理。

### 阶段三：严格音频时间线

1. 定义可插拔 `TimedSpeechEngine` 接口。
2. 接入能返回音频和字/词时间戳的 TTS 实现。
3. 以音频 `currentTime` 作为唯一主时钟。
4. Web Speech 保留为明确标记的兼容模式。

只有完成阶段三，才能对不提供可靠 `boundary` 的环境承诺从首字开始严格同步。

## 12. 测试方案

### 12.1 单元测试

- 规范化文本与 DOM 节点偏移双向映射。
- 中文、英文、跨标签、连续空白、NBSP、零宽字符、emoji。
- 范围起止和 chunk 绝对偏移。
- 时间戳插值、边界离群值过滤、暂停/恢复、语速改变。
- 控制器在不同 `dt`、掉帧和目标突变下无过冲、无不连续。
- 顶部、底部、页面不足一屏的 clamp 行为。

### 12.2 仿真测试

用假音频时钟和假页面几何输入以下轨迹：

- 匀速语音。
- 标点长停顿。
- 语速突然变化。
- 稀疏 `boundary`。
- chunk 末端无最后边界。
- 图片加载导致后文整体下移。
- 500ms 主线程卡顿后恢复。

记录每帧 `desiredTop`、`actualTop`、误差、速度和加速度，自动断言误差阈值及连续性。

### 12.3 浏览器集成测试

覆盖 Edge/Chrome、至少两个中文音色，并测试：

- 整章从顶部开始。
- 页面中段指定起点，结束文字为空。
- 明确起止范围。
- 标题、图片、长段落、英文混排章节。
- 播放、暂停、继续、停止。
- 播放中改语速、音色、阅读宽度和窗口大小。
- 用户滚轮、拖动滚动条、切后台、切章节。

调试模式输出结构化采样，不只打印单个锚点：

```js
{
  audioTime,
  spokenOffset,
  textY,
  desiredTop,
  actualTop,
  error,
  velocity,
  state,
  clockConfidence,
  layoutVersion
}
```

最后用录屏逐帧检查首播、跨行、chunk 边界、重排和章节切换，确认没有停顿后瞬移。

## 13. 推荐决策

推荐按三阶段实施，但从一开始就采用统一坐标、显式状态机和可插拔语音时钟，避免阶段三再次重写滚动层。

产品层面需确认一项取舍：

- 若“完美同步”是硬要求，必须接受带时间戳 TTS 引擎和播放前准备时间。
- 若必须只用浏览器内置 `speechSynthesis`，目标应改称“支持边界事件时高精度同步，无边界时平滑自适应”，不能承诺所有音色从首字起严格一致。

无论采用哪种语音引擎，首播前完成布局映射、使用真实字符 y、通过连续控制器滚动、大误差时暂停语音再对齐，是消除当前停顿和跳跃的共同基础。
