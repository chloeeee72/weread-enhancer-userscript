# 微信读书增强脚本：语音阅读代码审查与边界情况

> 审查对象：`src/modules/reading/voiceRead/` 下当前实现  
> 主要文件：`index.js`、`extractor.js`、`apiChapter.js`、`layoutMap.js`、`chunker.js`、`scrollFollower.js`  
> 版本：脚本元数据仍为 `1.29.0`

## 1. 当前已修复的问题回顾

1. **构建产物与源码不一致**
   - 此前 `dist/weread.user-1.29.0.js` 不包含 `extractCurrentPageContext` 等新逻辑。
   - 已重新构建，当前 dist 与源码一致。

2. **源码语法错误**
   - `index.js` 中 `handleFinish()` 后曾多一个 `}`，导致构建失败；已修复。

3. **章节 XHTML 重建不完整**
   - `apiChapter.getChapterHtml()` 之前只返回第一个 e_* 片段，导致隐藏排版 DOM 只有部分章节。
   - 已改为拼接全部片段，并处理：
     - 流式 `<body>` / `</body>`；
     - 未闭合 `<p>`；
     - HTML 前残句；
     - 损坏替换符；
     - e_2 CSS 资源内联。

4. **隐藏测量 DOM 不可测量**
   - `visibility:hidden` 导致 `innerText` 为空。
   - 已改为 `opacity:0`，并注入动态字体/行高样式。

5. **分页滚动映射错误**
   - 之前按“整章比例”映射当前页滚动距离，导致页首/页尾都落在页面中点。
   - 已改为按 `pageStartIndex/pageEndIndex` 做页内线性映射。

6. **“从文字”定位错误**
   - 优先使用文本层真实坐标；
   - 文本层不可用时，使用页内线性映射 + focusY 定位；
   - 不再信任 pre-render DOM 的绝对 y 和 canvas 的 pageStartY/pageEndY。

7. **第一页/末页边界缓存**
   - 记录第一页页尾 `pageEndIndex`；
   - 末页使用缓存恢复页首，避免从“第十三章”开始读。

## 2. 当前代码审查发现的问题

### 2.1 多页章节只区分“末页/非末页”，中间页无法表达

- `extractCurrentPageContext()` 通过底部按钮只能判断：
  - 有“下一页” → 非末页；
  - 有“下一章” → 末页。
- 对超过 2 页的章节，非末页统一被当作 `pageIndex = 0`，没有中间页概念。
- 影响：
  - 中间页的 `pageStartIndex/pageEndIndex` 无法准确得到；
  - 从中间页直接朗读可能仍会定位到第一页或末页边界。

建议：
- 后续如果遇到 3 页以上章节，需要从微信读书内部状态或连续翻页过程中累积“每页页尾缓存”，形成 `pageOffsets[]`。

### 2.2 第一页缓存依赖“先访问第一页页尾”

- `rememberFirstPageEnd()` 只在文本层可见且非末页时记录。
- 如果用户直接进入第二页且本浏览器从未在第一页页尾停留过，`getCachedFirstPageEnd()` 可能为空。
- 当前降级会走 canvas 比例，仍可能不够精确。
- 缓解：缓存已写入 `GM_setValue`，同一浏览器第二次访问会命中。

建议：
- 在首次进入末页且无缓存时，提示用户先翻到第一页页尾一次，或后续增加基于接口/内部状态的分页偏移探测。

### 2.3 文本层“可见窗口”被误当成整页边界

- `extractCurrentPageContext()` 文本层分支返回的是当前可见 passage 的范围，不是整页范围。
- 例如第一页底部时可能返回：
  - `pageStartIndex = 9590`
  - `pageEndIndex = 10297`
- 如果此时定位 `5296`（中间文字），会因小于 `9590` 被 clamp 到页顶。
- 当前已用“第一页整页缓存”缓解，但**未命中缓存时仍存在**。

建议：
- 文本层可见时，如果存在整页缓存，应优先使用整页边界；
- 文本层只用于“当前行真实 y 坐标”的定位，不应用来覆盖整页起止。

### 2.4 `pageOffsetToScrollTop()` 的“最后一屏”判定是启发式

- 当前逻辑：`raw >= distance - max(viewport * 0.5, 120)` 就滚动到底。
- 对于字号、行距、页边距变化较大的页面，该阈值可能偏大或偏小。
- 可能表现：
  - 最后几行被提前滚到底；
  - 或最后一行没有完全到底。

建议：
- 如果文本层可提供目标行真实 y，优先用真实 y；
- 线性映射只作为降级。

### 2.5 锚点（scrollAnchors）可能与页内线性映射冲突

- `prepareLayoutMap()` 仍会调用 `extractor.locateTextOffset()` 并调用 `addScrollAnchor()`。
- `addScrollAnchor()` 的误差是：
  - `err = measuredY - getViewportFocusY() - linearMapY(charOffset, distance)`
- 但 `measuredY` 来自 pre-render DOM 的绝对文档 y，而 `linearMapY` 是页内滚动位置，两者坐标系不一致。
- 一旦锚点表非空，`mapOffsetToScroll()` 会加上 `interpolateAnchorErr()`，可能重新引入错误偏移。

建议：
- 在分页模型下禁用锚点，或把锚点改为“文本层真实 y 与页内线性值”的误差；
- 当前 `mapOffsetToScroll()` 已不使用 layoutMap，但锚点仍可能干扰。

### 2.6 `locateTextOffset()` 仍可能被其它调用方用于 pre-render 坐标

- `jumpToRangeStart()` 已改为只使用 `locateTextOffsetInTextLayer()`。
- 但 `prepareLayoutMap()`、`scheduleAnchorMeasurement()` 仍调用通用 `locateTextOffset()`。
- 这些调用可能拿到 pre-render DOM 的绝对 y，并用于锚点/调试，存在上述坐标系风险。

建议：
- 朗读中若不需要锚点，可移除 `scheduleAnchorMeasurement()` 的调用链。

### 2.7 `isLastChapterPageByControls()` 可能误判

- 该函数扫描所有 `button/a/[class*="button"]` 的文本。
- 如果页面弹窗、目录、底部推荐位里出现“下一章/下一页”文字，可能误判当前页。
- 当前页面结构较稳定，但属于脆弱点。

建议：
- 只检查 `.readerFooter`、`.readerHeaderButton` 等阅读器专用容器。

### 2.8 `pageSignature` 依赖 scrollY，翻页等待可能假阳性/假阴性

- `getCurrentPageSignature()` 包含 `scrollY`、canvas 边界、控制按钮文本。
- 翻页后 scrollY 变化，签名大概率变化；
- 但用户手动滚动、弹窗出现、canvas 重绘也可能改变签名，导致 `continueToNextChapterPage()` 误判翻页完成。

建议：
- 翻页等待应优先检测“按钮从下一页变为下一章/上一页”或章节 uid 变化，而不是签名整体变化。

### 2.9 页面上下文缓存缺少内容版本校验

- `pageBoundaryCache` 的 key 是 `chapterUid:pageCount`。
- 如果同一 chapterUid 的正文内容因重修/版本变化而改变，旧缓存的第一页页尾可能失效。
- 当前未校验章节文本长度或内容 hash。

建议：
- key 中增加 `text.length` 或内容 hash。

### 2.10 `findApproximateTextRange()` 可能匹配到错误位置

- 文本层重建出现坏字时，会退化为“最长前缀匹配”。
- 如果前缀较短或过于常见，可能匹配到章节中其它相似位置。
- 当前要求前缀长度至少 8，已降低风险，但仍非绝对可靠。

建议：
- 匹配后增加“前后文校验”；
- 或同时用 `pageIndex`/按钮状态约束匹配范围。

### 2.11 `extractCurrentPageContext()` 中 layout 路径被禁用但代码/import 仍保留

- 已注释禁用 layout 反查页边界，但 `extractor.js` 顶部仍 import：
  - `getOffsetAtY`
  - `getOffsetAfterY`
- 这些 import 可能变成无用代码，增加包体积与维护成本。

建议：
- 清理未使用的 import 和注释块。

### 2.12 `voiceState.rangeTotalLength` / `getRangeStartFraction` / `getRangeEndFraction` 已基本无用

- 页内线性映射后，`getRangeStartFraction()`/`getRangeEndFraction()` 不再参与滚动计算。
- `rangeTotalLength` 只在赋值时保留，已无实际消费方。

建议：
- 后续可移除或改造成调试字段。

### 2.13 连续朗读跨页时 `voiceState` 旧状态清理风险

- `continueToNextChapterPage()` 调用 `loadAndSpeak()` 前没有主动 `stop()`。
- `loadAndSpeak()` 会 `sessionId += 1`、`sessionAbortController.abort()`，理论上能丢弃旧异步。
- 但旧 `speechEngine` 的 finish 回调可能仍触发 `handleFinish()`，需要确认 `sessionId` 判断足够覆盖所有路径。

建议：
- 在 `continueToNextChapterPage()` 翻页成功后，先 `speechEngine.stop()` 再 `loadAndSpeak()`，减少事件交叉。

## 3. 未充分考虑到的边界情况

1. **章节只有一页**
   - `pageCount = 1`，`isLastChapterPage` 应为 true。
   - 当前 `pageIndex = 0`，`pageEndIndex = text.length`，基本可用。
   - 但如果底部按钮同时出现“下一页/下一章”之外的元素，可能误判。

2. **用户手动滚动到页中间后点“朗读”**
   - `pageContext` 可能返回“可见窗口”而非整页，导致朗读范围不完整。
   - 建议朗读开始前始终用整页缓存/页边界修正。

3. **从文字填了下一页的文字**
   - `effectiveStart > pageEndIndex` 时，`rangeText` 为空，提示“没有可朗读文本”。
   - 用户预期可能是“自动跳到下一页再读”，当前未实现。

4. **到文字填了上一页的文字**
   - `endIndex < pageStartIndex` 时会被 `Math.max(effectiveStart, userEndOffset)` 纠正，但语义可能不符合预期。

5. **语速极快/极慢**
   - 滚动跟随依赖 `speechClock` 和 `getRemainingSeconds()`。
   - 边界事件不可用时走 L2 校准，首次可能跳动。

6. **页面 resize / 字体切换**
   - `scheduleLayoutRefresh()` 会重建布局，但分页模型下重建 layoutMap 可能无意义，且可能触发锚点错误。

7. **隐藏测量 DOM 的 CSS 加载失败**
   - 内联 CSS 来自 e_2，若某本书 e_2 不是 CSS 或缺失，隐藏 DOM 高度会偏离。

8. **GM 存储不可用**
   - `readPageBoundaryCacheFromStorage()` 已 try/catch，但缓存丢失后直接进入末页仍会退化为比例映射。

## 4. 建议的后续优化清单

- [ ] 建立多页 `pageOffsets[]` 缓存，支持 3 页以上章节。
- [ ] 文本层只用于“真实行 y”，整页边界优先使用缓存。
- [ ] 禁用或重构 scrollAnchors，避免坐标系混用。
- [ ] 翻页等待改为检测按钮状态/章节 uid，而不是整体 signature。
- [ ] 缓存 key 增加正文长度或内容 hash。
- [ ] 清理未使用的 layout import 和废弃 fraction 方法。
- [ ] 跨页续读前显式停止旧 speechEngine。
- [ ] 增加对“从文字在下一页/到文字在上一页”的明确处理。
