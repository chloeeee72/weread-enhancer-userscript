# 同章分页朗读问题排查与修复方向

> 状态：问题定位与修复已实施（仍需在目标页面回测）。
> 脚本版本：`1.29.0`
> 测试页面：
> <https://weread.qq.com/web/reader/49432980720c671f4941767kc0c320a0232c0c7c76d365a>
> 调试浏览器：Edge，CDP 端口 `9223`

## 1. 问题背景

微信读书网页版中，同一章节被拆成多页滚动阅读。当前脚本把“章节全文”作为朗读范围和滚动范围，导致两个问题：

1. 第十三章第二页直接点击“朗读”时，语音从第十三章第一页开头“第十三章，八盏明晃晃的学而灯”开始，而不是从第二页正文“你！！ 方孝孺和解缙均是当世大儒”开始。
2. 第十三章第一页通过“从文字”输入“可是要三思啊”后点击“朗读”，该文字是第一页最后一句，但页面自动滚动到了第一页中点附近，而不是该句所在位置；第一页读完也没有继续自动翻到第二页。

预期行为是：

- 朗读范围按当前可见页计算。
- 滚动范围按当前页实际正文位置计算。
- 第一页读完当前页末尾后，自动点击“下一页”，继续朗读第二页。
- 第二页是本章最后一页时，才走原有“等待下一章”逻辑。

## 2. 页面布局事实

第十三章有两页：

- 第一页滚动到底部后出现“下一页”按钮。
- 第二页滚动到底部后才出现“下一章”按钮。
- 如果某章节只有一页，滚动到底部后直接出现“下一章”按钮。

最后一轮回测时，页面停留在第十三章第二页，运行时观察到：

- `scrollY` 约 `10166.86`
- `scrollHeight` 为 `12076`
- `clientHeight` 为 `830`
- 页面按钮为“上一页”和“下一章”
- 页面包含两个 canvas 块，y 范围约 `[164, 2442]` 和 `[2451, 4725]`

## 3. 已确认根因

核心根因是：**当前实现没有“当前页”概念，把整章全文的长度和偏移都当作页面长度来计算。**

具体表现为：

- `extractCurrentChapterText()` 返回整章正文，接口、DOM、预渲染兜底都只提供整章文本。
- `chunker.applyRange()` 在整章归一化文本中查找“从文字”和“到文字”，返回的是整章字符偏移。
- `voiceState.textLength`、`timelineChunks`、`rangeStartIndex`、`rangeEndIndex` 都使用整章范围和整章偏移。
- `linearMapY()` 和 `mapOffsetToScroll()` 按整章范围做比例映射，因此第一页末尾的“从文字”会被映射到整章中点附近。
- 直接打开第二页时，没有“从文字”的情况下仍然从整章开头 `rangeStartIndex = 0` 开始，因此语音从第一页开头开始。
- `buildLayoutMap()` 也接收整章范围，并尝试用整章预渲染 DOM 建行映射；在第二页或缺少预渲染 DOM 时，无法表达“当前页实际起止位置”。
- `jumpToRangeStart()` 的降级逻辑使用 `startIndex / totalLength` 映射整章滚动距离，也会导致“从文字”定位到错误位置。
- `handleFinish()` 只检测 `chapterUid` 是否变化，不检测同章节内的“下一页”，所以第一页读完不会续读第二页。

## 6. 修复方向

### 6.1 增加当前页边界提取

优先从运行时可见文本层或预渲染 DOM 中重建当前页文本，并在整章归一化文本中定位：

- `pageStartIndex`
- `pageEndIndex`
- `pageIndex`
- `pageCount`
- `isLastChapterPage`
- `pageSignature`
- `pageStartY`
- `pageEndY`

页面起点来源需要同时考虑：

- 当前可见文本层中的 `[data-wr-role="text"]` 字符 span
- 翻页期间预渲染 DOM 中的当前页文本
- 微信读书内部状态中可能存在的 `pageOffsets`、`pageCount`、`currentPage`、`currentSectionIdx`

运行时拿不到 DOM 文本层时，不能继续用整章比例估算，否则问题仍会复现。

### 6.2 朗读范围改为页内范围

修改 `loadAndSpeak()` 的范围计算：

- 没有“从文字”时，使用 `[pageStartIndex, pageEndIndex]`。
- 有“从文字”时，`effectiveStart = max(userStartIndex, pageStartIndex)`。
- 未指定“到文字”或“到文字”越过页末时，`effectiveEnd = pageEndIndex`。
- `voiceState.textLength`、`timelineChunks` 使用页内文本切片。
- 字符偏移仍保留整章归一化文本的绝对偏移，供 `locateTextOffset()` 和布局映射使用。

### 6.3 布局与滚动映射改为页内

- `layoutMap.js` 的 `buildLayoutMap()` 接收页内边界。
- `linearMapY()`、`mapOffsetToScroll()` 使用当前页起止偏移，不再使用整章比例。
- `prepareLayoutMap()` 优先测量当前页的 `pageStartY/pageEndY`。
- `jumpToRangeStart()` 优先定位“从文字”在当前页 DOM 中的真实 y 坐标，避免降级到整章比例中点。

### 6.4 同章跨页续读

修改 `handleFinish()`：

1. 当前不是最后一页且开启续读时，停止滚动并触发 `autoPageTurn.trigger()`。
2. 等待 `pageSignature` 变化。
3. 调用 `loadAndSpeak({ continuation: true, sameChapterPage: true, expectedChapterUid: voiceState.chapterUid, rejectText: '' })`。
4. 只有最后一页才保留原有“等待下一章”逻辑。

注意：同章续读时 `expectedChapterUid` 与当前章节相同，`rejectText` 不能设为整章文本，否则 `extractReadableChapter()` 会把当前章节正文误判为“下一章尚未加载”而拒绝。

### 6.5 补充测试

至少覆盖：

- 同一章多页时，无“从文字”的范围为当前页文本。
- 同一章多页时，“从文字”落在当前页内，范围为当前页内。
- 同一章多页时，“从文字”在当前页之后，不从当前页开头硬读。
- 第一页读完后能进入同章“下一页”续读。
- 最后一页读完后仍等待下一章。
- 页内字符偏移与整章归一化偏移保持一致。

## 8. 约束与注意事项

- 必须保留脚本版本 `1.29.0`。
- 构建时使用 `npx vite build`，不要使用 `npm run build`，避免版本号被自动升级。
- 工作区目前有大量未跟踪文件，不回滚、不清理、不删除。
- 接口只提供整章正文，不提供分页信息，修复不能依赖接口分页字段。
- `autoPageTurn.trigger()` 已被验证可触发翻页，可复用于同章翻页。
- 当前页面缺少文本层 DOM、预渲染 DOM 和 Webpack require 时，需要先补齐页面边界来源，否则无法稳定修复。

## 9. 已实施的修复

- `apiChapter.getChapterHtml()`：暴露已捕获的整章 XHTML，供运行时重建隐藏排版 DOM。
- `extractor.extractCurrentPageContext()`：新增当前页边界提取。
  - 优先使用文本层 DOM 重建当前页文本；
  - Canvas 模式下用 `.wr_canvasContainer canvas` 边界，结合预渲染 DOM 或 API XHTML 重建的隐藏排版 DOM，反查页首/页尾在整章文本中的偏移；
  - 仍拿不到测量 DOM 时，按 canvas 高度比例切分整章，避免把整章都算到第一页。
- `voiceRead.loadAndSpeak()`：朗读范围改为“当前页内范围”。
  - 无“从文字”时从当前页页首开始；
  - “从文字”早于当前页时从当前页页首开始；
  - 结束文字越过页末时截断到当前页页末；
  - `voiceState` 增加 `pageStartIndex/pageEndIndex/pageIndex/pageCount/isLastChapterPage/pageSignature`。
- `voiceRead.handleFinish()`：同章非最后一页读完时触发 `autoPageTurn.trigger()`，等待 `pageSignature` 变化后以 `continuation` 方式继续朗读下一页；最后一页仍走原有“等待下一章”逻辑。
- `voiceRead.jumpToRangeStart()`：降级定位改为按当前页边界计算，不再用整章比例导致跳到页中点。
- `layoutMap.getOffsetAfterY()`：新增页尾排他边界反查，供页面边界测量使用。
